## Findings

### 1. Exercise 3's solution rewrites `Package`, `charge()`, and the printed value beyond what the exercise asked

- **Severity:** drift
- **Where:** `Chapters/20_Patterns--Rethinking_Objects.md:1133-1139` (exercise 3),
  `Solutions/20_Patterns--Rethinking_Objects.md:112-154` (`exercise_3.py`)
- **Exercise says:** "In `protocol_collision.py`, define `Price = NewType("Price", float)` and
  `Weight = NewType("Weight", float)`, change `Priced.total()` to return a `Price`,
  `Weighted.total()` to return a `Weight`, and `Package.total()` to return a `Weight`. Run
  `ty check` and read the error it reports for `charge(package)`."
  This names exactly three return-type annotations to change, on the existing
  `protocol_collision.py` structure (`Package` is `@dataclass(frozen=True)` with a `weight_kg:
  float` field, `total()` returns `self.weight_kg`, `charge()` returns `float`, and
  `print(charge(package))` prints `4.5`).
- **What actually happens:** I built the minimal edit the exercise actually describes — same
  `Package(weight_kg: float)` frozen dataclass, same `charge() -> float`, same `package =
  Package(4.5)`, only the three return annotations changed — and ran it:
  `uv run ty check work/20/exercise_3_minimal.py` reports the identical diagnostic quoted in the
  solution's prose (`invalid-argument-type` / "type `Package` is not assignable to protocol
  `Priced`" / "incompatible return types: `Weight` is not assignable to `Price`"), and
  `uv run python work/20/exercise_3_minimal.py` prints `4.5`, matching the chapter's original
  output. So the exercise as literally stated is fully satisfiable with a three-line edit that
  keeps everything else in place.
  The Solutions listing instead deletes the `weight_kg` field and the `@dataclass(frozen=True)`
  decorator from `Package`, hardcodes `total()` to `return Weight(2.5)` (a different number
  than the chapter's `4.5`), and rewrites `charge()` from `-> float: return item.total()` to
  `-> str: return f"${item.total():.2f}"`, changing the printed output from `4.5` to `$2.50`.
  None of this is asked for by the exercise text.
- **Solution does:** Produces the same `ty` diagnostic (verified) but under a visibly different
  program than the one a reader following the exercise literally would write, with a different
  printed value (`$2.50` vs. the chapter's own `4.5`) and a `Package` that no longer has the
  `weight_kg` field or frozen-dataclass status the exercise's target file has.
- **Suggested fix:** Trim `exercise_3.py` back to the minimal edit: keep `Package(weight_kg:
  float)` as `@dataclass(frozen=True)`, keep `total()` returning `Weight(self.weight_kg)`, keep
  `charge()` returning `float`, and keep `package = Package(4.5)` / `print(charge(package))`
  printing `4.5`. The `ty` error and its explanation carry over unchanged (confirmed above); only
  the invented `$`-formatting and the field/decorator removal need to go.
