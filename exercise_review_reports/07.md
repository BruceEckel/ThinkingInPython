## Notes

1. **`shrink()` on `Circle` (`property_setter.py`).** Added
   `shrink(self, factor): self.radius = self.radius / factor` to a copy
   of `Circle`. `Circle(10).shrink(2)` -> `c.radius == 5.0`. Calling
   `shrink(-2)` on that same circle (`5.0 / -2 == -2.5`) raised
   `ValueError: radius cannot be negative`, and `c.radius` stayed
   `5.0` afterward (setter is doing the validation, not silently
   storing the negative value). Matches the exercise's stated numbers
   exactly. Solution's `exercise_1.py` runs to `5.0` /
   `caught: radius cannot be negative`, matching.

2. **`from_kelvin()` on `Temperature` (`class_methods.py`).** Added
   `from_kelvin(cls, k): return cls(k - 273.15)`. Built
   `Temperature.from_fahrenheit(212)` and `Temperature.from_kelvin(373.15)`
   (same physical temperature, water's boiling point): both give
   `celsius == 100.0`, agreeing within rounding as asked. Solution's
   `exercise_2.py` runs to `100.0 100.0`, matching.

3. **`Simple3` chain (`simple2.py`).** Added
   `Simple3(Simple2)` overriding `show()` to print its own message
   then `super().show(msg)`. `Simple3("x").show_twice()` produced, per
   call: `Simple3` message, `"Overridden show() method"`, then `"x"`
   (twice, once per `show_twice()` call) — the derived-to-base chain
   the exercise asks the reader to predict. `Simple2` and `Simple3`
   both exist and both override `show()` as the exercise assumes.
   Solution's `exercise_3.py` (a self-contained copy of `Simple`/`Simple2`
   with constructor prints removed, noted in its own prose) produces the
   same chain shape; solution's own note about why it drops the
   constructor prints is accurate.

4. **`average` cached property (`cached_property_demo.py`).** Added
   `@cached_property def average(self): return self.total / len(self.values)`.
   Accessing `n.total` then `n.average` printed `"summing 3 values"`
   only once (at the `n.total` access) — `average`'s use of
   `self.total` did not retrigger `total`'s computation, confirming
   the exercise's stated claim. Solution's `exercise_4.py` matches
   (adds its own `"computing average"` trace print, an embellishment
   consistent with the chapter's existing style for `total`, not a
   defect).

5. **`__repr__()`/`__str__()` on `Temperature`.** With only
   `__repr__() -> f"Temperature({self.celsius})"` added,
   `print(Temperature(21.0))` and `print([t, t])` both show
   `Temperature(21.0)` (repr fallback). After also adding

   `21.0C` / `[Temperature(21.0), Temperature(0.0)]` /
