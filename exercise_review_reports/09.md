## Findings

### 1. Exercise 5 uses `field(default_factory=list)`, a technique the chapter explicitly defers to chapter 12

- **Severity:** minor
- **Where:** `Chapters/09_Foundations--Class_Attributes.md:422` (exercise text),
  contradicting the chapter's own deferral at
  `Chapters/09_Foundations--Class_Attributes.md:122-123`
- **Exercise says:** "Rewrite `Cart` from `shared_mutable.py` as a `@dataclass`
  with `items: list[str] = field(default_factory=list)`..."
- **What actually happens:** The chapter's own prose, two paragraphs after
  `shared_mutable.py`, says: "A mutable default belongs in a `@dataclass` field
  with a `default_factory`, covered in [Data Classes as
  Types](12_Techniques--Data_Classes_as_Types.md#data-classes)." — i.e. the
  chapter explicitly states this technique is taught in chapter 12, two
  chapters later. `grep -n "field(" Chapters/09_Foundations--Class_Attributes.md`
  and a scan of every `from dataclasses import ...` line in chapters 01-09 show
  `field` (the singular per-field customizer, distinct from the `fields()`
  function chapter 9 does show in `dataclass_no_annotation.py`) is never
  imported or demonstrated anywhere at or before this chapter. The reader
  reaches exercise 5 having seen only `from dataclasses import dataclass,
  fields`, never `field`.
  Practically this is not blocking: the exercise spells out the exact
  expression to type (`items: list[str] = field(default_factory=list)`), so a
  reader who copies it verbatim and adds `from dataclasses import dataclass,
  field` (a small, guessable extension of the pattern already shown) succeeds.
  Confirmed by running the rewrite cold:
  `uv run python ex5.py` with
  ```python
  from dataclasses import dataclass, field

  @dataclass
  class Cart:
      items: list[str] = field(default_factory=list)

  a, b = Cart(), Cart()
  a.items.append("apple")
  print(a.items, b.items)
  ```
  produces `['apple'] []`, matching `Solutions/09_Foundations--Class_Attributes.md`
  exercise 5 exactly. So the exercise is doable and its solution is correct;
  the only defect is that the chapter names `default_factory` as future
  material, then requires it in this chapter's own exercises.
- **Solution does:** Uses `field(default_factory=list)` and
  `from dataclasses import dataclass, field` without comment, matching what the
  exercise asked; no drift between exercise and solution here.
- **Suggested fix:** Either (a) drop the deferral language at line 122-123 (say
  chapter 9 also introduces `field`/`default_factory` in passing), or (b) add one
  line to the chapter body actually showing `from dataclasses import field` and
  `field(default_factory=...)` before the exercises, or (c) reword exercise 5 to
  not require the reader to independently supply the import. Any of the three
  resolves the inconsistency; which one is a judgment call for the author.
