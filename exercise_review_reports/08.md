## Findings

### 1. Solution 6's quoted `ty` diagnostic does not match real `ty` output (wrong line number and wrong message)

- **Severity:** wrong
- **Where:** `Solutions/08_Foundations--Static_Types.md:196-202`
- **Exercise says:** (`Chapters/08_Foundations--Static_Types.md:716-718`)
  "In `type_aliases.py`, call `paint(grid, (2, 3), "purple")` and run
  `ty check`. Read the error, then widen `Color` to admit `"purple"` and
  confirm the error goes away."
- **What actually happens:** Reproduced by taking the chapter's actual
  `type_aliases.py` (`build/examples/08_Foundations--Static_Types/type_aliases.py`,
  14 lines) and changing only line 12's `"red"` to `"purple"` (the call the
  exercise names), leaving `Color` unwidened:
  ```
  uv run ty check type_aliases_exact2.py
  ```
  gives:
  ```
  error[invalid-argument-type]: Argument to function `paint` is incorrect
    --> type_aliases_exact2.py:12:21
     |
  12 | paint(grid, (2, 3), "purple")
     |                     ^^^^^^^^ Expected `Color`, found `Literal["purple"]`
  info: Function defined here
   --> type_aliases_exact2.py:8:5
    |
  8 | def paint(grid: Grid, cell: Coord, color: Color) -> None:
    |     ^^^^^                          ------------ Parameter declared here
  ```
  The `paint()` call sits at line **12**, and `ty` 0.0.75 (`uv run ty
  --version`) reports **`Expected \`Color\``** (the alias name), not the
  literal spelled out.
- **Solution does:** Solutions quotes a diagnostic at **line 14**, reading
  `Expected \`Literal["red", "blue", "green", "yellow"]\`, found
  \`Literal["purple"]\``, and its prose builds an explicit claim on that
  wording: "The diagnostic spells out the expected type in full even
  though `paint()` names it as `Color`... the alias costs nothing in the
  error message." That claim is false against the actual tool: `ty` names
  the alias (`Color`), it does not spell out the literal union, and the
  call is at line 12, not 14.
- **Suggested fix:** Replace the quoted diagnostic block with the real
  one (line 12, `Expected \`Color\`, found \`Literal["purple"]\``) and
  drop or rewrite the sentence that claims the diagnostic spells out the
  literal in full, since it does the opposite (it collapses to the alias
  name). This may be a stale capture from an older `ty` version rather
  than a hand-typo; either way the current text is contradicted by
  `ty` 0.0.75, the version pinned in this repo.
