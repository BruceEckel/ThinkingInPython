## Findings

### 1. Exercise 6's solution swaps in a different `group_rounds()` than the one the exercise names

- **Severity:** drift
- **Where:** `Chapters/41_Functional--Toolkits.md:1063-1066`
  (`Solutions/41_Functional--Toolkits.md:166-186`)
- **Exercise says:** "`group_rounds()` takes a `seed` and builds its own
  `random.Random`. Replace that with an `rng: random.Random` parameter.
  Which property of the function does that preserve, and which one does
  it hand to the caller?"
- **What actually happens:** The `group_rounds()` the exercise names is
  the one built through "Case Study: Pairing Rotations"
  (`build/examples/41_Functional--Toolkits/student_pairs.py`), with a
  `met()` closure, a `history: Counter[frozenset[str]]`, and a
  greedy nearest-candidate loop. Performing the exercise mechanically on
  that real function (only replacing `seed: int = 0` with
  `rng: random.Random` and deleting the internal
  `rng = random.Random(seed)` line, nothing else) works with no
  difficulty and reproduces the chapter's own sample rounds:
  ```
  0 [('Gia', 'Eve', 'Ana'), ('Di', 'Cy'), ('Fi', 'Bo')]
  1 [('Di', 'Bo', 'Eve'), ('Cy', 'Ana'), ('Gia', 'Fi')]
  2 [('Eve', 'Fi', 'Ana'), ('Bo', 'Gia'), ('Cy', 'Di')]
  deterministic: True
  ```
  (run via `uv run python ex6_real.py` on a copy of the edited function
  in scratch). So the mechanical edit the exercise asks for was not hard
  to make on the real function; no simplification was needed to answer
  it.
- **Solution does:** Defines a `group_rounds()` under the same name and
  the same "Injecting the random source" heading, but with a wholly
  different body: `pool = list(students); rng.shuffle(pool); yield
  [tuple(pool[i:i+size]) for i in range(0, len(pool), size)]`. It drops
  `met()`, the `history` Counter, and the greedy least-met selection
  entirely, replacing the case study's algorithm with plain fixed-size
  chunking of a shuffled list. The prose answer ("preserves determinism,
  hands the caller control of the seed") happens to hold for both
  versions, and I confirmed it holds for the real function too — so the
  *conclusion* the solution reaches is right, but the code shown is not
  an edit of the function the exercise names; it is a different,
  simpler stand-in with the same name.
- **Suggested fix:** Show the edit against the real `group_rounds()`
  from `student_pairs.py` (keep `met()`/`history`, change only the
  `seed`/`rng` parameter and the one line that built `random.Random`
  internally), since the real edit is no harder to present and matches
  what a reader who just read the case study would expect to see
  changed.
