## Findings

### 1. Exercise 4 asks two questions; Solution 4 answers one

- **Severity:** drift
- **Where:** `Chapters/38_Patterns--Simulation.md:1259-1260`
  (`Solutions/38_Patterns--Simulation.md:538-572`)
- **Exercise says:** "Explain why the factory finds your new item on its
  own, / and what it does if you derive `Coin` from `Food` instead."
- **What actually happens:** the second question has a definite answer,
  which I reproduced. `item_factory()` walks `Item.__subclasses__()`,
  which reports only *direct* subclasses, so a `Coin(Food)` is invisible
  to it and the `$` falls through to the "anything else is a teleport
  target" line:

  ```
  $ uv run python ex4b.py
  factory on '$': Teleport
  finished: False coins: 0
  ```

  With five `$` in `string_maze` the builder turns them into five
  `Teleport` rooms, `zip(pairs, pairs)` pairs only four of them, the
  maze's topology changes, and the hard-coded `solution` no longer
  reaches the `!`. (Stepping onto the unpaired fifth would raise an
  `AttributeError` on the unset `target_room`.)
- **Solution does:** the prose at lines 561-572 explains `__subclasses__()`
  and why `Room` and `GameBuilder` need no change. The word "Food"
  appears in the whole Solutions file only twice: as the `class Food`
  definition (line 417) and in a comment "Collected, like `Food`"
  (line 551). The derivation question is never addressed.
- **Suggested fix:** add a paragraph to Solution 4: `__subclasses__()`
  lists direct subclasses only, so a `Coin(Food)` never appears on the
  list the factory searches; the `$` then reaches the fallback and
  becomes a `Teleport`, and the character silently becomes a teleport
  target instead of a coin.

### 2. Exercise 4 says "the robot maze"; Solution 4 uses a three-line toy maze

- **Severity:** minor
- **Where:** `Chapters/38_Patterns--Simulation.md:1255,1257`
  (`Solutions/38_Patterns--Simulation.md:555-558`)
- **Exercise says:** "Add a new kind of `Item` to the robot maze. ...
  Place a few `$` characters in the maze and report how many the robot
  collects."
- **What actually happens:** the exercise is doable as written on the
  chapter's `string_maze`. Replacing five `_` cells that lie on the
  robot's path with `$` gives `finished: True coins: 5` and leaves no
  `$` in `show_maze()`.
- **Solution does:** a three-line toy maze (a two-coin
  `R$$.#` row between `#####` walls) with `game.run("ee")`,
  printing `2`. It never touches `string_maze`, while Solution 5
  does reproduce `string_maze` in full.
- **Suggested fix:** either place the `$` in `string_maze` (the coins
  must sit on the path the hard-coded `solution` walks, or the count is
  zero), or reword the exercise so it does not name "the robot maze",
  e.g. "Place a few `$` characters in a maze".
